
---

### Структура
---
1) dags - папка с DAG
2) docker-scripts - там лежат все докерфайлы сервисов
3) lambda_func - папка с Lambda-функциями и её зависимостями
4) localstack_scripts_init - скрипт, который инициализирует бакет, DynamoDB-таблицы и Lambda-функцию
5) logs - папка для логов Airflow
6) scripts - папка для Spark-скриптов
7) data - папка с csv (orig - большая csv, splits - маленькие разделённые по месяцам - из неё и работают DAGs)
---

### Как работает
---
1) Разделение большого датафрейма на мелкие по периодам запускается через split_dag отдельно
2) Далее должен отрабатывать load_into_bucket_dag
3) Затем идёт создание аргументов для скрипта DynamicTaskMapping, которые идут в LivyOperator
4) Livy нужен, чтобы соединять Airflow с поднятым Spark-сервисом (использовать готовый, а не как в DockerOperator, и чтобы не ставить java-зависимости на стороне Airflow-контейнера)
5) При загрузки любой csv в бакет (как на этапе Python, так и из Spark), начинает отрабатывать lambda, которая загружает информацию в DynamoDB таблицы
6) Также есть DAG, который выгружает информацию из DynamoDB, чтобы по ним можно было построить дашборды в Tableau (Использовалась public версия, а connection из DynamoDB в Tableau не предусмотрен)

<br>
ПРИМЕЧАНИЕ: может это не самый оптимизированный код, но если хотите как разраб запустить сразу 4 воркера на и обрабатывать не один период, а все - (34 изначальных csv + ещё 34 после Spark), съест 24 ГБ оперативы
